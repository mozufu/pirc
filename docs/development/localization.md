# Client localization

Web and the Flutter client provide **English** and **繁體中文** in Settings → General → Language.
English is both the initial language and fallback, independently of the OS language.
The selection belongs to the local client: Web uses `pirc-language` in localStorage;
the Flutter app keeps it with its local settings so background UI can read it.

## Catalogs

- Web: `apps/web/src/lib/locales/{en,zh-TW}.json`, via `tr` in `i18n.svelte.ts`.
- Flutter: `apps/app/lib/l10n/app_{en,zh,zh_TW}.arb`, generated by `flutter gen-l10n`
  into `app_localizations*.dart`. `app_zh_TW.arb` inherits `app_zh.arb`, the base
  Traditional Chinese catalog required by gen-l10n.
- Native Android: `apps/app/android/app/src/main/res/{values,values-zh-rTW}/strings.xml`,
  via Android string resources for system notification actions, overlay UI and native errors.

Translate whole sentences. Numbered placeholders such as `{0}` are replaced only
after lookup; their values can be user-authored names or content and must remain
literal. Never translate API keys, paths, CSS selectors, terminal sequences, model
identifiers, user messages or rendered document content. Some historical Chinese
source strings remain lookup keys, but their English catalog values define the default.
Missing keys use the English value (or source); an intentionally empty translation
is valid for an English plural suffix.

After changing Flutter catalogs, run from `apps/app`:

```sh
flutter gen-l10n
flutter test test/app_shell_test.dart
cd android && ./gradlew testStandardDebugUnitTest --tests org.mozufu.pirc.StringsTest
```

The ARB key test and the `strings.xml` key test check key and placeholder parity.
Widgets subscribe through the generated `AppLocalizations`; the application root
only rebuilds for appearance or language changes, not each stream event. Translation
changes must retain input focus, editing selection and the IME composing range. The
initial Traditional Chinese catalogs were translated/reviewed with 6Luna subagents and
integrated locally.

Account or server-provided error details can still arrive in the language supplied
by the server. Provider/model names, code identifiers and key labels remain literal.
