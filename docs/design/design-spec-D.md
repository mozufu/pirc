# pirc 行動版設計 · 統一對話增補（方向 D）

版本 0.2 · 2026-11-05 · 依據 `mozufu/pirc` `b6f2f41`：`plans/unified-conversations.md`、`plans/conversation-execution-contracts.md`、`plans/pots/design.md`、`docs/guides/pots.md`、`plans/checkpoints.md`、`docs/guides/calendar.md`，以及目前的 `apps/web`、`apps/android`（Flutter）。

這份文件只描述**因架構調整需要改的前端**。沒有提到的部分沿用 `design-spec.md`（方向 C）、`components.md` 與 `tokens.json`，不另行變更。原型在 Design 畫布「D · 統一對話（架構調整）」頁，畫面編號 D1–D20。原型是網頁模擬，不能直接編譯成 App。

## 0. 實作狀態標示

| 標示 | 意思 | 對應 |
|---|---|---|
| 無 | 已實作或已有後端 | pots 追蹤／開始／接管、專案指示與檔案、第一次送出的草稿與復原（未啟用）、行事曆 |
| 開發中 | 後端進行中，尚未開放 | U2 工作區綁定與來源、U4 工作區切換與撤銷 |

計畫中 U3（導覽與 UI）明確延後；本文件就是 U3 的設計提案，不代表後端已提供對應能力。

## 2. 導覽（D1）

側欄由上而下：

1. 品牌列：π、搜尋（對話與專案）、關閉。
2. **新對話**。
3. **pots**：深色 π 圖示，副標「n 項待決定 · n 個建議」，右側待決定數。
4. **需要你處理**：跨所有對話的等待項目（問題、核准、錯過排程、記憶提案），依到期排序。
5. **專案**：可展開；展開後列出成員對話與狀態點（執行中、等待）。＋ 新增專案。
6. **其他對話**：不屬於任何專案的對話；From pots 的對話在副標標示。
7. 已封存（數量）。封存只改組織，不停止工作；封存中仍有執行中或需要你的項目，要在「需要你處理」出現。
8. 底部：行事曆（原「排程」入口）、設定（含 Gateway 連線狀態）。

拿掉：聊天／工作切換、依裝置分組的工作區清單。主機與工作區改成對話的屬性（見第 3、6 節）。平板沿用 C 的寬度規則。

## 3. 新對話與工作區設定（D2、D3）

- 首頁輸入框上方一列兩個小膠囊：專案、工作區（「Laptop · ~/pirc · +1」）。點任一個打開工作區設定。
- 工作區設定的內容：
  - **專案**：選了會帶入專案的資料夾與規則，並顯示規則版本。
  - **主機（Node）**：在線可選；離線或不相容的顯示原因、不可選。
  - **主要資料夾**：來自專案／受管理的空資料夾（一般聊天預設，第一次送出時才建立）／選擇現有資料夾／建立新資料夾（只能在允許的位置，按下就建立）。
  - **其他掛載**：每列標示名稱、路徑、來源（來自專案／這個對話）、權限；新增的掛載預設唯讀。
  - **這個對話可以做的事**：依實際權限列出，例如讀寫 ~/pirc、讀取 docs、執行指令、瀏覽器未啟用。
- 這些選擇存在草稿；只有第一次被接受的送出才建立對話。草稿不會出現在對話清單。
- 第一次送出的狀態沿用已實作的復原流程：送出中、不確定是否送達（只提供「檢查狀態」，不重送）、被拒絕（「再送一次」是另一個明確動作）。

## 4. 對話中的任務（D7、D8）

- 頂部**任務列**：每個任務一個膠囊（字母代號、名稱、狀態一行），點開任務詳情。沒有任務時不顯示。
- 開工時對話中出現「已建立 n 個任務」卡，列出各任務與它用的工作區。
- 每次任務更新只出現**一行動態**（任務代號、摘要、狀態）；工具細節收在任務詳情與工具卡。
- 針對某任務的提問與回答，上方標示「問題／回答 · 關於 A」，並註明 A 仍在執行。
- 輸入框上方「傳給」：
  - 自動判斷（預設；判斷不出來時先問一個簡短問題）
  - 指定任務（修正或補充）
  - 新任務（不影響既有任務；資源不足時排隊並說明）
  - 只是問問題
- 一般訊息不會停止任何工作。停止只在任務詳情或任務列上。
- 執行中且輸入框空白時，主按鈕不再是「停止」（因為可能有多個任務）；改用任務上的停止。

## 5. 任務詳情（D9、平板 ②）

- 狀態膠囊、來源（你的要求或 From pots）、工作區與權限。
- **進度**：真實步驟（2 / 5），不顯示估算百分比；最後一步可以是「等你驗收」。
- **子工作**、**產出**（變更檔案 +n −n、測試結果）、**被它擋住的工作**（等待寫入的任務與路徑）。
- 底部：暫停、停止任務…（只停這個任務與它的子工作；已寫入的不還原）、驗收（只有在「待你驗收」時可按）。
- 停止後顯示「停止中」，直到主機確認；主機離線時停在「停止中」。

任務狀態全集：提議中、已就緒、排隊中（附原因）、執行中、等你回答、等資源（持有者與路徑）、等前置任務、待你驗收、已完成、停止中、已停止、失敗、不確定是否完成（只能「檢查狀態」）。見狀態板。

## 6. 工作區面板與切換（D10–D13）

- 對話標題下方的工作區一行（狀態點＋主機＋主要資料夾＋掛載數）可點，打開工作區面板。
- 面板內容：主機與連線、資料夾（來源與權限）、**現在的狀態**（可用、唯讀、等你核准、等資源分開顯示）、變更（切換主機、變更資料夾與掛載、封鎖某個資料夾、讓對話離開專案）。
- **切換前預覽（D11）**：確認後會中斷什麼、什麼留在原主機（未提交變更、開發伺服器）、新主機上有什麼與缺什麼（同名資料夾不代表同內容）。取消不會有任何變化。
- **套用中（D12）**：上方資訊橫幅與三段進度（停止舊工作、撤銷舊權限、準備新工作區）；期間可閱讀、草稿保留、不能送出。對話時間軸記下一筆「你把工作區從 A 換到 B」，說明哪個任務被中斷、可能有部分變更。
- **原主機離線（D13）**：停在「等待確認」，不在新主機開始、也不恢復舊權限；提供「改選主機…」。
- 被切換影響的排隊任務會等新工作區準備好，**不會自動改目標**。

## 7. pots（D14–D16、平板 ③）

- 入口在側欄頂部，與對話分開；不是另一堆聊天。
- **狀態卡**：觀察中／暫停、協調中／暫停（附「恢復協調…」）、派工額度與同時執行數。
- **需要你決定**：pots 執行中對話的問題與核准，直接前往回答。
- **建議**：每張卡寫出「為什麼」與來源；動作是查看來源、只追蹤、開始…、稍後、略過。讀過不等於接受。
- **開始（D15）**：寫下你授權的指示；說明會在同一個工作區建立新的執行對話、對方看到 From pots、使用多少額度。
- **追蹤中的任務**：完成不等於驗收。
- **職責**：目的、觀察範圍（只看進度或可讀內容）、狀態與用量。
- **pots 協調中的對話（D16）**：上方深色列「由 pots 協調中」＋接管；未接管前輸入框只能回答問題或停止；From pots 訊息標示授權來源，不是你直接傳的。接管後改成一般橫幅。
- 各控制要寫清楚範圍：暫停觀察、暫停協調、接管、停止任務、恢復，不要只有一個「暫停 pots」。

## 8. 專案（D4–D6）

分頁：對話、資源、規則、筆記、看板。

- **資源**：共用資料夾（主機、路徑、權限）；「變更資源…」前先列出受影響的對話與任務。核准方式與委派設定也在這裡。
- **規則**：只有你能改，有版本；在下一個安全的回合邊界套用。agent 只能提出修改，待你檢視。
- **筆記**：有版本、有作者的共用事實。
- **看板**：有作者的訊息（你、任務、From pots）；明確寫出「不會鎖檔案、不給權限」。
- 選單：封存專案、刪除專案…。

## 9. 離開、封存、刪除（D17–D19）

- **離開專案預覽**：會移除（專案資料夾、規則、筆記與看板存取）、會中斷（執行中任務）、保留（對話與歷史、已保存附件）、仍有的獨立權限（另外授權過的資料夾，要移除需另外封鎖）。
- **離開後的對話**：上方說明已離開；時間軸記下這次變更；專案檔案參照顯示「無法開啟：你已離開專案」，已保存的節錄仍在。
- **刪除專案預覽**：會先停止、會刪除（專案擁有：對話、規則、筆記、看板、專案排程、在這些對話建立的記憶）、不會刪除（掛載的資料夾與提交、檢查點與復原工作區、其他對話引用的內容）、需要你決定（混合來源的記憶）。主機離線時停在「等待停止」。
- 封存只改組織，不停止工作，不需要預覽。

## 10. 檔案參照

- 已保存的附件：依附件本身的權限開啟。
- 專案／工作區檔案參照：每次開啟、預覽、下載都要目前權限；顯示來源主機與讀取時間。
- 無法開啟時分開說：沒有權限、主機離線（可看標示時間的快取）、檔案已不存在。不自動重試權限錯誤，也不換成別的檔案。

## 11. 通知（D20）

依重要性設定，每類可選立即／摘要／不通知：

| 類別 | 預設 |
|---|---|
| 需要你決定（問題、核准、阻塞、標記緊急） | 立即 |
| 完成與建議（一般完成、pots 非緊急建議） | 摘要〔規劃〕 |
| 進度（工具進度、沒變化的狀態） | 不通知，只更新任務 |
| 行事曆提醒 | 立即 |

摘要時間與勿擾預設值待定。略過或稍後的建議保持安靜，直到情況有實質變化。每則通知都對應保存好的項目；通知沒送到也不會遺失。

## 12. 行事曆（D21–D30、平板 ⑤⑥）

現有功能（`docs/guides/calendar.md`、`schedules.md`），行為不變；只有 Agent 任務的執行目標受架構影響。

**沿用，依 C 風格補畫**
- 入口：側欄底部「行事曆」，有錯過的執行時顯示「1 錯過」。
- 檢視：月／週／日／清單用分段控制切換；時區顯示在標題下。
- 標記用形狀區分，不只靠顏色：個人事件＝圓點（`accent.default`）、全天＝長條、Agent 任務＝菱形（`action.primary`）、錯過＝黃色菱形＋「錯過」文字。
- 月檢視：下方列出選取日的項目；今天用墨色實心圓。
- 週／日檢視：個人事件是色塊（`accent.soft`），Agent 任務只標時間點（沒有長度）；目前時間線用 `status.danger`。長按拖曳只開草稿，按「儲存」才會變更。
- 個人事件：標題、全天、開始／結束、時區、重複、最多 5 個提醒、地點。不會啟動 agent；提醒由 Gateway 推播。
- 重複事件修改範圍：只有這一次／這一次和之後／整個系列（改時間、時區或規則會清除個別改過的日期）。
- Agent 行事曆權限：「允許讀取」與「允許提出變更」分開，預設都關閉；排程能力、完整存取或專案設定都不會自動給予。
- 對話中的變更提議：用互動卡顯示前後差異與過期時間；套用前重新檢查版本與權限，多台裝置同時按只套用一次；拒絕後對話留下一行紀錄。
- 錯過的執行不自動補跑：在 Agent 任務面板顯示「允許補跑／略過」。

**因架構調整而改**（標「開發中」）
- Agent 任務的「在哪裡執行」改成選「專案＋工作區（主機、主要資料夾）」；每次執行開一個新對話，用所選工作區的權限，不繼承原對話的核准。
- 執行目標被移除（離開專案、移除掛載、工作區切換）時：排程暫停，清單與面板顯示「已暫停：執行目標已無法使用」，列出原本的目標；**不會自動改到別的地方**。重選目標後按「儲存並恢復」才恢復；沒選之前按鈕停用。
- 執行紀錄寫出沒執行的原因（例：「沒有執行：執行目標已移除」）。
- 離開／刪除專案、移除掛載的預覽（D17、D19）要把會受影響的 Agent 任務列在「會中斷」。

後端需求：排程記錄目標的專案與綁定版本；目標失效時回傳 blocked 狀態與原因；修正目標是一次有版本的更新。
