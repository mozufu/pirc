# pirc 行動版設計規格（方向 C）

版本 0.2 · 2026-09-30 · 依據：pirc commit `c4b7dd3` 的 web／Android 原始碼、`01-DESIGN-BRIEF.md`、`02-SCREEN-STATE-MAP.md`，以及設計討論中的決定。本版納入使用者確認的 1A／2A／3A。

原型在 Design 畫布「C · 網頁風格（目前方向）」頁。原型是網頁模擬，**不能直接編譯成 App**；本文件和 `tokens.json`、`components.md` 才是給 Flutter 實作的依據。文中「#n」指畫布上手機總覽的畫面編號。

標記：**〔現有〕** 原始碼已有的能力，本次只重做版型；**〔提案〕** 新能力，需要設計或工程新增；**〔後端〕** 需要後端配合，見第 10 節。

## 3. 版型規則（依可用寬度，不依裝置）

| 寬度 | 版型 |
|---|---|
| < 600（手機、507 分割視窗） | 單欄。側欄是覆蓋式抽屜；成果、工作面板、終端都是整頁，左上返回 |
| 600–839（768 直向） | 平常：側欄 280＋對話。開右欄時：對話 50%｜右欄 50%，側欄改覆蓋式 |
| ≥ 840（1024 橫向） | 平常：側欄 280＋對話（正文限寬 680）。開右欄時：側欄收起，對話 480｜右欄其餘；☰ 可叫回覆蓋式側欄 |

縮放時必須保留：目前的對話與捲動位置、輸入框草稿、右欄內容（成果或工作面板分頁）與其捲動位置、已展開的區塊。寬度變窄時右欄轉成整頁，返回時回到對話原位置；變寬時再轉回並排。

- 平板保留 24 上／12 下的系統區域，內容不可被裝置圓角裁切。
- 右欄同一時間只放一種內容：成果或工作面板。聊天的工作面板只有 4 個分頁（無 Git、終端），和網頁一致。

## 4. 導航與返回

返回（系統返回鍵、手勢、左上鍵）依以下順序關閉最上層：

1. 鍵盤 → 2. 底部面板（sheet）／子清單 → 3. 側欄 → 4. 全螢幕成果、工作面板、終端 → 5. 回到來源畫面。

- 全螢幕成果關閉後回到原本那張卡片，卡片外框高亮 1 秒，草稿保留。
- 工作面板返回回到對話；全螢幕終端返回回到終端列表。
- 從通知進入的對話，返回回到側欄的工作模式，而不是關掉 App。
- 子清單（模型、思考強度）選完自動回到上一層。

## 5. 輸入區與鍵盤

- 輸入框（composer）：大圓角浮起面板；工具列有附件（＋，無外框）、模型與思考（一個按鈕）、送出。
- 執行中且輸入框空白時，主按鈕是「停止」〔現有行為〕；開始打字後主按鈕變「送出」，停止移到旁邊的次要按鈕。
- 送出時機切換：「引導」（steer，目前工具步驟完成後加入）／「排隊」（follow-up，這輪結束後送）〔現有〕。
- 目標／todo／佇列放在輸入框上方的 dock〔現有〕；鍵盤開啟時收成一列。
- 停止的文案不可寫成「停止全部」：只保證停止目前工作。
- 鍵盤與 IME 候選列出現時，輸入框與送出鍵一定可見；對話列表以底部為錨點。
- 自動捲動：只有使用者已在底部時才跟著串流捲動；在讀舊訊息時不跳動，改顯示「有新內容 ↓」；問題卡出現且不在畫面內時，顯示「有問題等你回答 ↓」。
- 離線時草稿保留，重連後**不會**自動送出。

## 6. 待處理、通知與快速回應

### 6.1 四個層級
| 層級 | 呈現 |
|---|---|
| 對話內 | 問題卡、工具失敗、寫入受阻就在對話裡，動作靠近原因 |
| App 內 | 鈴鐺數字、首頁橫幅、側欄「待你處理」列 |
| 持久入口 | 「待處理與動態」面板：上半部待處理（依到期），下半部最近動態（時間序）〔提案〕〔後端〕 |
| 系統 | Android 通知、下方快速回應視窗 |

看過不等於處理完：項目只有在回答、執行或略過後才離開「待處理」。

### 6.2 點通知之後（所有入口共用）
1. 直接開啟 App 畫面（Android 12 起不可經由中介 service 轉跳）。
2. 整頁「正在重新連線並取得最新狀態」，此時不顯示可操作按鈕。
3. 依結果分成五種：
   - 仍有效 → 對話頁＋確認面板，預選通知上點的答案，按「送出答案」才送出。
   - 已被處理 → 「這項已經處理過了」，顯示處理者與時間〔後端〕。
   - 已過期 → 問題卡標示已過期，不能回答。
   - 控制權在其他裝置 → 確認面板上方顯示「由 ○○ 控制中」與「取得控制權」〔現有〕。
   - 離線 → 保留預選，顯示「無法確認最新狀態」，只有「重試」。

### 6.3 Android 通知元件（見通知元件板）
- 收合：標題＋問題；動作「回答…」「開啟對話」。
- 展開：自訂版面，最多 3 個選項；超過 3 個、複選、輸入、editor 類只給「開啟對話回答」〔提案〕。
- 錯過排程：「查看並執行」「略過…」（按鈕文字帶「查看」或「…」，表示會先確認）。
- 即時進度：常駐通知，不定長度進度條；Android 16 起可用 ProgressStyle，舊版降級〔提案〕〔後端〕。
- 已由其他裝置處理：更新內容後 5 秒自動收回〔提案〕〔後端〕。
- 鎖定畫面：依設定產生公開版本（隱藏內容／只顯示標題／全部）；選項按鈕只在解鎖後出現。

### 6.4 下方快速回應視窗〔第一版必備，待實作〕
App 自己繪製、顯示在其他 App 上層的底部浮窗（需使用者授予「顯示在其他應用程式上層」權限；未授權就改用一般通知）。
- 開發順序：先完成 Android 技術驗證，再展開完整介面移植。驗收項目見 `flutter-validation.md`；一般 App 內的 bottom sheet 不算跨 App 浮窗驗證。
- 開啟時先顯示「確認最新狀態…」，按鈕不可按；確認後才開放選項與送出，因此可以直接在視窗內送出。
- 狀態：確認中、可回答、已送出（自動關閉）、已被處理（只顯示結果與「好」）。
- 右上：開啟完整對話、關閉。關閉不算處理，項目留在待處理。
- 視窗底部顯示控制權來源（「控制：此裝置」）。

## 7. 成果容器〔提案〕

| 狀態 | 卡片 | 全螢幕／右欄 |
|---|---|---|
| 生成中 | 標題＋「生成中…」＋可讀的部分摘要；主要動作停用 | 可開啟閱讀已產生的部分，底部顯示仍在生成 |
| 完成 | 類型小標、標題、一行摘要、來源數；主要動作「開啟」；複製、分享 | 內容＋頂部可回溯到原訊息 |
| 更新中／有新版本 | 小標顯示新版本號 | 保留目前閱讀版本及位置，頂部提示「已有 v2」；使用者按「切換」才載入新版；各版本分別保存閱讀位置，新版首次從頂端開始 |
| 失敗 | 失敗原因＋重試（向 agent 提出請求） | 顯示最後一個可用版本 |
| 不支援此類型 | 退回 Markdown 摘要＋「在網頁開啟」 | 同左 |

動作分兩類，在 UI 上要分開：只改本地顯示（切換版本、展開、複製）與會向 agent 或遠端提出請求（重試、重新產生）。

## 8. 工作面板

- 入口：對話頂部的狀態小膠囊（分支、變更數、終端數、檔案），或右上面板鍵。
- 分頁：六格等寬，圖示＋文字，數字徽章（Git 變更數、終端數、背景工作數）。
- Git：分支與領先數、變更檔案（點開 diff）、最近提交；只提供檢視〔現有〕。commit／PR 管理為未來設計。
- 檔案：路徑導覽、標出有變更的資料夾、agent 最近開過的檔案。
- 終端列表：說明文字、新終端（需控制權）、每個終端顯示名稱、路徑、欄×列、狀態；已結束可移除〔現有，同 Android TerminalsPane〕。
- 全螢幕終端：一律深色；字元畫面最新一行貼底；點畫面叫出鍵盤並重算列數；鍵盤上方額外按鍵列（Esc、Tab、Ctrl 可按住、Alt、方向鍵、常用符號）；頂部字級與更多（複製、貼上、清除、關閉）。沒有另外的輸入框。沒有控制權時畫面唯讀，底部顯示「取得控制權」。
- Tasks：背景指令（可停止）、teammates、任務板、訊息〔現有〕。
- 記憶：狀態（unavailable／disabled／working／idle）、最近觀察附來源、反思預設收合〔現有〕。記憶提案在設定審核。
- 瀏覽器：預覽畫面標出 agent 正在點擊的位置、接管／歸還、分頁數、錄影狀態、操作紀錄〔現有〕。

## 9. 狀態涵蓋

原型已畫：串流中（composer 停止鍵）、等待回答、已回答、送出中、寫入受阻、錯過排程各狀態、已被其他裝置處理、確認中、深色、鍵盤開啟、空狀態（Tasks／記憶／瀏覽器的空版本寫在 components）。

規格已定、原型未畫（實作時照此做）：

| 狀態 | 規則 |
|---|---|
| 首次／未配對 | 單頁配對：掃 QR 或貼連結；驗證中、失效、成功 |
| 沒有 chat node | 首頁「在哪裡開始」只列 workspace；聊天項目顯示原因 |
| 載入中 | 列表用骨架列；對話用最後快取內容＋頂部細進度條 |
| 離線 | 頂部一條「離線 · 顯示的可能不是最新狀態」；所有會送出的按鈕停用；草稿保留 |
| 重新連線 | 同上，文字改「重新連線中…」；成功後自動消失，不重送任何命令 |
| 結果不明 | 命令送出後斷線：顯示「不確定是否已送達」＋「檢查狀態」，不自動重送 |
| 控制權被占用 | 輸入框上方一列「由 ○○ 控制中」＋「取得控制權」；輸入框唯讀 |
| 核准過期 | 問題卡變淡並標示「已過期」，按鈕移除 |
| 工具失敗 | run card 以文字＋ ✕ 標示，展開看輸出 |
| 大字體 | 依系統字級縮放；最大時頂部標題只留一行、列表副標可折兩行；觸控區不縮小 |
| 430 寬手機 | 同 390 版型，正文寬度隨螢幕；不額外加欄 |

## 11. 新增後端能力清單

1. **處理紀錄**：interaction 與錯過排程的處理者裝置名稱、時間、結果；推送「已處理」事件讓其他裝置收回通知。
2. **活動事件與歷史**：session 開始、步驟、完成、失敗；可分頁查詢（最近動態）。
3. **通知偏好**：每個推送目標訂閱的類別、勿擾時段、workspace 靜音（由 server 或 App 過濾，待定）。
4. **推播 payload**：interaction id、runnerEpoch、expiresAt、最多 3 個選項；點選後 App 仍要重新取得 snapshot。
5. **即時進度**：目前步驟文字與更新時間（需節流）。
6. **一般完成／失敗通知類別**：目前 gateway 只推排程、待回應、委派、記憶提案。
7. **成果**：版本化內容、更新事件、可回溯到訊息 id、類型與 renderer fallback 資訊。
8. **iOS**（後續版本）：APNs 推播，不列入第一版範圍。
9. 快速回應視窗本身是 App 端工作，但依賴 1 與 4。

## 13. Flutter 實作提示

- 主題：`tokens.json` 的每一組轉成 `ThemeExtension`（例如 `PircColors`、`PircType`、`PircElevation`），light／dark 各一份；元件只讀語意名稱。
- 版型：頂層 `LayoutBuilder` 依寬度選 compact／medium／expanded；三種版型共用同一個狀態（目前 session、草稿、右欄內容與捲動位置），切換時不重建資料。
- 返回：用巢狀 Navigator／`PopScope` 依第 4 節順序處理。
- 鍵盤：`MediaQuery.viewInsets` 決定輸入框位置；對話 `ListView(reverse: true)` 以底部為錨點。
