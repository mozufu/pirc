# pirc 設計規則

給後續 `pirc-design` skill 使用。分成兩部分，用途不同：

- **A. 開發 App 介面**：寫 pirc 的 web／Flutter UI 時遵守。
- **B. agent 產生可展示內容**：agent 在對話中決定用段落、表格、圖表、文件或互動面板。

所有規則都指向 `tokens.json` 的語意名稱與 `components.md` 的元件名稱；不要在程式或內容中寫死色碼。

---

## A. App 介面規則

### A1. 顏色
1. 用語意 token，不用原始色碼；light／dark 由主題切換，元件不判斷主題。
2. `accent.default` 只用在：選取狀態、連結、執行中狀態、主要但非「送出」的按鈕。不要用 accent 填大面積（進度條、橫幅、整塊背景）。
3. 送出、完成這類最終動作用 `action.primary`（墨色）。
4. 狀態色當文字時用 `text.warning`／`text.success`，不要直接用 `status.*`。
5. 黃色（warning）只用在點、數字、小標與小面積底色；不做滿版黃色橫條。
6. 終端一律用 `color.terminal.*`，不跟隨 App 主題。

### A2. 區隔與層次
1. 每個表面只用一種區隔：浮起的用 `elevation.*`，成組的用底色（`surface.subtle`／`fill.hover`／`surface.layer` on `surface.grouped`），細線只用在表格、列表分隔、欄位分界。
2. 不要同時使用外框和陰影；選取狀態可以用 1–1.5px 內框。
3. 深色模式沒有可見陰影，層次靠 `surface.page` → `surface.layer` → `surface.subtle` 的明度差。
4. 白色元件放在淺底上時，底色要至少到 `surface.grouped` 的深度，否則改用 `fill.hover` 當元件底色。

### A3. 字與版面
1. 字級只用 `typography` 內的級別；中文內文與列表用 400，按鈕與待處理項目 500，標題 600。
2. 手機左右邊距 16；側欄文字左緣 24；分組列表文字左緣 32。
3. 手機頂部標題以螢幕置中；平板窗格內標題靠左。
4. 圖示：頂部 22、列表 18、行內 16，線寬 1.75，Lucide 風格。
5. 觸控區至少 44，建議 48；密集資訊也不縮小觸控區。
6. 正文限寬 680。

### A4. 版型與返回
1. 依可用寬度選版型（`layout.compact／medium／expanded`），不依裝置型號。
2. 切換版型時保留：目前 session、捲動位置、草稿、右欄內容與位置。
3. 開啟右欄時收起側欄；寬度不足時右欄轉整頁。
4. 返回順序：鍵盤 → 面板 → 側欄 → 整頁內容 → 來源畫面。
5. 從成果或面板返回時，回到原本的訊息並短暫高亮。

### A5. 狀態與安全語意
1. 狀態一律「文字＋符號」，不只靠顏色（✓ 完成、✕ 失敗、◆ 等待、◐ 執行中）。
2. 會改變遠端狀態的動作（回答、執行、略過、停止、送出），在離線、確認中、沒有控制權時停用，並說明原因。
3. 從通知、卡片、快速回應視窗進入的動作，先重新取得最新狀態再開放按鈕；不自動送出。
4. 失聯後不宣稱成功、不自動重送；顯示「不確定是否已送達」與「檢查狀態」。
5. 停止按鈕只描述「停止目前工作」。
6. 控制權（誰能操作 session）與寫入權（哪個 session 能寫 workspace）分開顯示。
7. 已讀不等於已處理。

### A6. 動畫
1. 只用 `motion.fast`（150）與 `motion.sheet`（250）；減少動畫時停止脈動與旋轉。

## B. agent 內容呈現規則

agent 回覆時依內容性質選擇呈現方式。預設是段落；只有內容本身需要時才升級。

| 內容 | 用 | 元件 | 規則 |
|---|---|---|---|
| 回答、解釋、建議、少於約 3 個重點 | **段落** | MessageAssistant | 先給結論；不要為了排版加標題 |
| 3–7 個並列步驟或重點 | **清單** | MessageAssistant | 每項一句；超過 7 項考慮表格或文件 |
| 兩個以上選項在多個面向的比較、規格對照 | **表格** | 訊息內表格；列數 > 5 或欄數 > 3 改成 ResultCard（比較表） | 第一欄是面向；手機可橫向捲動，最多 4 欄 |
| 趨勢、分布、比例、需要看形狀的數字 | **圖表** | ResultCard（圖表），摘要寫出最重要的數字 | 用 accent 與中性色；圖表下一定附文字結論；資料可展開成表格 |
| 會被保存、分享、之後再讀的長內容（報告、計畫、規格），或超過手機一個畫面的內容 | **文件** | ResultCard（文件）→ ResultReader | 卡片放一行結論；文件內要有來源；更新時產生新版本 |
| 使用者需要調整輸入、看結果變化（估算、篩選、設定組合） | **互動面板** | ResultCard（互動）→ 受控容器 | 標明哪些操作只改本地顯示、哪些會向 agent 或遠端提出請求；不支援時退回表格＋說明 |
| 需要使用者做決定才能繼續 | **問題** | QuestionCard | 用 select／confirm／input／editor；選項 ≤ 3 時會出現在展開通知上；寫出每個選項的影響與成本 |
| 檔案、diff、指令輸出 | **連結到工作面板** | RunCard、GitView、FileBrowser | 對話中只放摘要與路徑，完整內容在工作面板 |

補充規則：
1. 一則回覆最多一張 ResultCard；需要多份成果時，拆成多則回覆或一份文件分節。
2. ResultCard 的摘要必須能獨立讀懂（手機上常只看卡片）。
3. 所有成果都要能回溯到產生它的訊息，並列出來源。
4. 生成中也要給可讀的部分內容；失敗時保留上一個可用版本。
5. 渲染器不支援的類型，一律退回 Markdown 摘要＋「在網頁開啟」。
6. 不要用顏色單獨表達結果（例如表格中的好壞），要加文字或符號。
